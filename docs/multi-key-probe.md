# 多模式按列盘点说明

## 目标

本功能支持两种 OpenAI 兼容 API 的模型级批量检测：

- 多 Key 模式：同一个 Base URL 下输入多枚 API Key。
- 多 Base URL 模式：同一枚 API Key 下输入多个 Base URL。

两种模式都会先逐列拉取 `/models`，合并模型并集，再对用户选中的、且该列已经列出的模型执行原子探测。列可以是一枚 Key，也可以是一个 Endpoint。

## 行为契约

- 用户必须显式选择多 Key 或多 Base URL 模式。
- 多 Key 模式中，Base URL 只有一个；每行输入一枚 API Key。
- 多 Base URL 模式中，API Key 只有一枚；每行输入一个 Base URL。
- API Key 只保存在当前页面内存状态，不写入 `localStorage`。
- Base URL 输入、当前模式、并发数和 prompt 会写入 `localStorage`。
- `/api/models` 和 `/api/check` 的后端接口保持单次原子请求形态。
- 模型列表来自所有成功返回的 `/models` 结果并集。
- 批量检测只调用该列 `/models` 已列出的模型组合。
- 总并发数作用于模型拉取和批量检测队列。
- 批量检测任务按列轮询排队，让多个 Key 或 Endpoint 更早同时出现进度。
- 当任务数超过 100 时只提示风险，不阻止用户继续。

## 结果语义

结果按当前模式下的比较对象分组：

- 多 Key 模式：每组是脱敏后的 API Key。
- 多 Base URL 模式：每组是自动命名的 Endpoint 和压缩后的 Base URL。

每组只显示该 Key 或 Endpoint 在 `/models` 中列出的、且被用户选中的模型。没有被该列列出的模型不会在该组中显示，也不会调用 `/api/check`。

每个模型项独立显示：

- `待检测`：任务已生成但尚未开始，或尚未运行批量检测。
- `检测中`：该组合正在调用 `/api/check`。
- `可用`：上游返回成功，并尽可能展示首字延迟。
- `不可用`：上游返回错误、超时或代理层请求失败。

结果过滤按实际可探测组合计数：全部、可用、不可用或待完成。

## 大批量注意事项

前端负责队列调度，避免把完整任务集提交给单个长时间运行的函数。建议默认从 3 到 5 的总并发开始。如果 Key 数、Endpoint 数或模型数较多，先通过模型选择器缩小范围，再逐批检测，避免触发上游限流或消耗过多函数额度。
