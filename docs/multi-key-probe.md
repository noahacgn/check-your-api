# 多 API Key 矩阵探测说明

## 目标

本功能把原来的单密钥检测扩展为同一个 OpenAI 兼容 Base URL 下的多密钥矩阵检测。用户输入多枚 API Key 后，应用会逐个拉取模型列表，合并模型并集，再对每个 `Key × 模型` 组合执行一次原子探测。

## 行为契约

- Base URL 只有一个；每行输入一枚 API Key。
- API Key 只保存在当前页面内存状态，不写入 `localStorage`。
- `/api/models` 和 `/api/check` 的后端接口保持单次原子请求形态。
- 模型列表来自所有成功返回的 `/models` 结果并集。
- 即使某个 Key 的 `/models` 没有列出某个模型，矩阵检测仍会实际调用该 `Key × 模型` 组合。
- 总并发数作用于模型拉取和矩阵检测队列。
- 当任务数超过 100 时只提示风险，不阻止用户继续。

## 结果语义

矩阵行表示模型，列表示脱敏后的 API Key。每个单元格独立显示：

- `待检测`：任务已生成但尚未开始，或尚未运行批量检测。
- `检测中`：该组合正在调用 `/api/check`。
- `可用`：上游返回成功，并尽可能展示首字延迟。
- `不可用`：上游返回错误、超时或代理层请求失败。

单元格中的 `未列入 /models` 只表示该 Key 拉取模型列表时没有返回这个模型；它不会跳过实际探测。

## Vercel 免费版注意事项

应用部署到 Vercel Hobby 时仍使用短生命周期的 serverless 函数调用。前端负责队列调度，避免把完整矩阵提交给单个长时间运行的函数。

建议默认从 3 到 5 的总并发开始。如果 Key 数和模型数较多，先通过模型选择器缩小范围，再逐批检测，避免触发上游限流或消耗过多 Vercel 函数额度。
